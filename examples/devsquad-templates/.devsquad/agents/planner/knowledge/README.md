# planner knowledge

각 파일이 무엇이고 언제 참고할지 한 줄씩. 총량이 30k 토큰을 넘으면 이 설명을 기준으로 선별 주입된다.

| 파일 | 내용 | 언제 |
|---|---|---|
| `use-case-guide.md` | 유스케이스 4절 작성법과 좋은/나쁜 예 | 항상 |
| `prd-checklist.md` | 빠뜨리기 쉬운 요구사항 점검 목록 (권한, 동시성, 빈 상태, 삭제 정책, 알림) | 완료 기준 점검 시 |
| (여기에 추가) `domain/*.md` | 프로젝트 도메인 규칙, 정책 문서, 법규 요약 | 관련 기능 기획 시 |

## 넣어야 할 것
- 이 프로젝트에만 있는 정책 (예: 탈퇴 유예 30일, 무료 플랜 한도)
- 과거 기획 결정 기록 (왜 그렇게 했는지)
- 외부 시스템 제약 (결제사 규정, 앱스토어 심사 기준)

## 넣지 않아야 할 것
- 일반적인 기획 방법론 설명 (LLM이 이미 안다)
- 소스 코드
