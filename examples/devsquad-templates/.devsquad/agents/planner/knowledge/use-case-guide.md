# 유스케이스 작성 가이드

## 형식
```
### UC-<3자리>: <동사로 끝나는 제목>   예) UC-012: 북마크를 컬렉션으로 이동한다
- 행위자: 로그인 사용자
- 사전조건: 사용자가 최소 1개의 컬렉션을 가진다
- 주 흐름:
  1. 사용자가 북마크 카드의 "이동"을 선택한다
  2. 시스템이 사용자의 컬렉션 목록을 보여 준다
  3. 사용자가 대상 컬렉션을 선택한다
  4. 시스템이 북마크의 소속을 변경하고 결과를 표시한다
- 대안·예외 흐름:
  - A1 (2에서) 컬렉션이 없으면 "새 컬렉션 만들기"를 먼저 제안한다
  - E1 (4에서) 대상 컬렉션이 삭제되어 있으면 오류를 표시하고 1로 돌아간다
- 사후조건: 북마크는 정확히 하나의 컬렉션에 속한다
```

## 좋은 예 / 나쁜 예
- 나쁨: "사용자가 북마크를 편리하게 관리할 수 있다" — 행위도 결과도 없다.
- 좋음: "UC-003: 태그로 북마크를 필터링한다" — 시작 조건과 끝 상태가 있다.
- 나쁨: 예외 흐름 없음 — 개발자가 오류 처리를 임의로 정하게 된다.
- 좋음: 네트워크 오류, 권한 없음, 대상 없음 세 가지는 대부분의 UC에 존재한다. 없다면 왜 없는지 한 줄 적는다.

## 자주 빠지는 것
- 빈 상태(데이터 0건)에서의 화면
- 삭제의 의미 (hard/soft, 복구 가능 여부, 연쇄 삭제)
- 권한 (본인 것만? 공유된 것도?)
- 동시 수정
- 목록의 정렬·페이지 기본값
