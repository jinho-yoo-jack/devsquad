# 20. Go 통합 서비스 구현·검증

기록일: 2026-10-06. 기준: [19-Go-통합-서비스-설계.md](19-Go-통합-서비스-설계.md). 기존 두 Go 서비스 + Temporal 구현을 단일 `devsquad` 서비스로 전환했다. 이 문서의 결과는 이번 통합 구현을 직접 실행한 결과다.

## 트랜잭션과 복구

- 생성 전에 원본을 독립된 workspace로 복사하고 Git 기준 커밋을 만든다. pipeline JSON은 `task.pipeline`에, 팀원·프롬프트 정의는 보호된 `.devsquad-runtime/definition.json`에 고정한다. 생성 트랜잭션이 실패하면 workspace를 제거한다. 단 COMMIT 응답이 끊겨 성공 여부가 불명확하면 파일을 보존하고 DB 복구·고아 정리에 맡긴다.
- 동일 Task의 Reconcile은 직렬화하고, 실행 중 Stage는 registry에서 중복 실행을 막는다. claim마다 `attempt`가 증가하며 결과는 `attempt`, `status`, `version` 조건이 모두 맞아야 커밋된다.
- 모든 상태 변경 경로는 Task 행을 먼저 잠근다. 승인 결정, Stage 전이, 재시도 수, 이벤트 저장이 함께 성공하거나 함께 롤백된다. `resume_pending`은 사용하지 않는다.
- Stage에 필요한 선행 단계만 모두 approved이면 즉시 실행한다. 병렬 단계 중 하나라도 리뷰 상태라면 Task는 waiting_approval이다.
- pause는 진행 중 단계를 마치도록 두며 새 실행을 막는다. cancel은 커밋 후 context를 취소하고 늦은 결과를 버린다. 일반 실행 실패는 Task failed와 형제 단계 취소로 처리한다.
- blocked에서 수동 resume하면 blocked_reason의 게이트 종류에 따라 planning/executing으로 복귀한다. retry 번호는 유지하여 기존 승인 행과 충돌하지 않게 한다.
- execute 시작 시 해당 단계의 write_paths에 속한 파일만 승인 기준점으로 복원한다. 승인 후 Reconcile이 Git 커밋과 `refs/devsquad/approved/<stage>`를 만든다. 마지막 승인 직후 종료되는 경우를 위해 completed Task도 파일 기준점 마무리를 재확인한다.
- Task별 이벤트 번호 증가와 이벤트·usage INSERT는 같은 트랜잭션이다. 커밋 성공 후에만 Bus가 전달한다. 타임스탬프는 PostgreSQL 정밀도인 마이크로초로 정규화한다.
- 고아 workspace는 DB Task에 없고 1시간 이상 지난 것만 정리한다. 새 생성과 충돌을 줄이기 위한 유예 시간이다.
- 서비스 시작 시 DB 세션 advisory lock으로 동일 스키마의 두 번째 인스턴스를 거부한다. lease 컬럼은 아직 사용하지 않는다.

쓰기 경로 충돌 검사는 glob의 고정 경로 접두어를 보수적으로 비교한다. 서로 겹칠 가능성이 있는 팀원·단계는 생성 시 거부하므로 쓰기 소유 경로를 명확히 나누어야 한다. 파일 도구는 실제 symlink 경로까지 검사하며 workspace 밖, 시크릿, 다른 단계의 쓰기 경로로 우회할 수 없다.

## 직접 실행한 검증

- 전체 Go 테스트에 race detector 적용, `go vet ./...`, 단일 바이너리 빌드.
- 실제 PostgreSQL: goose 신규·반복 적용, 승인 12개 동시 요청 중 1개 성공/11개 409, 두 승인 종류의 반려·수정, 상한 blocked와 수동 resume, pause/resume/cancel, 실패 시 형제 취소.
- 이벤트를 저장한 트랜잭션을 강제로 롤백했을 때 이벤트·usage·seq·Bus 발행이 모두 롤백됨. DB CHECK와 pending approval 유일 제약 확인.
- 중복 Reconcile 30회에도 runner 중복 실행 없음. 실행 중 context 종료 후 새 orchestrator가 중단된 단계만 재실행하고, 미완성 파일을 제거하며 승인된 다른 단계 파일을 보존함.
- 선행 단계가 끝난 후 다른 병렬 단계의 승인을 기다리지 않고 다음 단계 실행. REST와 WS 재생 envelope 일치와 연속 seq 확인.
- SDK HTTP fixture: OpenAI tool call/result 왕복, Anthropic system cache_control과 복수 tool result, 캐시 사용량, 429 재시도와 취소.
- 실제 OpenAI `gpt-4o-mini`: 계획 → write_file → 완료, 3회 호출, 합산 입출력 796 tokens. 테스트가 만든 파일과 usage_record를 확인했다. 실제 Anthropic·Ollama 서비스 호출은 이번 검증에 포함하지 않았다.
- Docker 이미지 빌드 및 실행. 승인 대기에서 SIGKILL 후 재시작한 예제의 6개 Stage 모두 approved, 승인 9건, 이벤트 89건의 연속 seq, `/metrics` 200 확인. 동일 DB의 두 번째 컨테이너는 시작 거부.
- Go 전환 시점에는 웹 변경 없이 타입 검사, Vitest 26개, Next.js 프로덕션 빌드 통과. 이후 추가 요청에 따른 에이전트 현황 기능과 최신 웹 검증은 [21-에이전트-작업-현황.md](21-에이전트-작업-현황.md)에 별도 기록한다.

실제 모델 테스트는 `DEVSQUAD_REAL_LLM_TEST=true`일 때만 실행한다. 기본 테스트와 CI에서는 외부 모델을 호출하지 않는다. 재현 명령은 [README](../README.md#검증)를 참고한다.

## 운영·전환 제한

단일 인스턴스와 로컬 workspace가 전제다. 모델의 실제 호출은 중단 복구 때 반복될 수 있으며, 이미 기록한 사용량은 보존한다. `run_tests`는 저장소의 신뢰된 설정 명령을 실행하며 OS 수준의 격리 컨테이너를 단계마다 만드는 구조는 아니다.

기존 Flyway/LangGraph/Temporal 체크포인트는 자동 변환하지 않는다. 별도 새 DB로 전환하고 기존 데이터를 보존한다. 개발용 `make resetdb`는 지정 Compose 프로젝트의 DB·workspace 볼륨을 삭제한다. 이번 검증은 전용 테스트 인프라만 사용했다.

Discord/GitHub 통합은 `notify.Notifier`, `scm.Publisher` 인터페이스와 no-op까지만 제공한다. GitHub clone/push/PR은 후속 범위다. 토큰 예산 강제와 단일 사용자 JWT 인증은 이후 구현했다(15-API §1·§2·§3).
