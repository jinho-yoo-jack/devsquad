# 디자인 — 정보 구조와 화면 설계

> [!tip] 핵심 Takeaway
> 웹 UI의 존재 이유는 두 가지다. **보는 것**(네 agent가 지금 무엇을 하는지, 무엇을 만들었는지)과 **결정하는 것**(승인·반려·수정). 그래서 핵심 화면은 Task 상세 하나이고, 그 화면은 "파이프라인(위) — agent 카드 + 타임라인(가운데) — 산출물 뷰어 + 승인 패널(오른쪽)"의 3구역 레이아웃으로 고정한다. 나머지 화면(Task 목록, Agent 설정)은 이 화면으로 들어오고 나가는 통로다.

← [[11-시스템-아키텍처]] · 다음: [[13-Frontend-설계]]

## 1. 디자인 원칙

첫째, **관찰은 요약으로, 결정은 원문으로.** 타임라인과 agent 카드에는 요약만 흐르고, 승인 패널에서는 Plan·Deliverable 원문을 그대로 보여 준다. 사람이 보고 결정하는 대상에 요약을 끼우면 책임이 흐려진다.

둘째, **대기 중인 결정이 항상 가장 눈에 띈다.** 어느 화면에 있어도 헤더에 대기 승인 수가 보이고, Task 상세에서는 승인 패널이 우선 노출된다.

셋째, **agent는 사람처럼 보이되 사람으로 오해되지 않게.** 역할별 아바타와 색을 주지만 이름은 "기획 agent", "Backend agent"처럼 직무명으로 고정한다.

넷째, **다크 테마 기본.** 사용자가 주로 다크 테마 도구를 쓰고, 타임라인·diff 뷰어가 다크에서 더 읽기 좋다. 라이트도 토큰으로 지원한다.

## 2. 정보 구조(IA)

```
/                         → /tasks 로 리다이렉트
/tasks                    Task 목록 (프로젝트 선택기 포함)
/tasks/new                새 Task (명령 입력)
/tasks/:id                Task 상세 ★ 핵심 화면
/tasks/:id/deliverables/:did   산출물 전체 화면 뷰어 (모달 대체)
/projects                 Project 목록·연결 (GitHub repo)
/projects/:id/agents      Agent 설정 (persona / conventions / knowledge 편집)
/projects/:id/pipeline    pipeline.yaml 시각 편집 (Phase 3)
/settings                 Discord 연결 상태, 토큰 예산, 알림
```

전역 헤더는 프로젝트 선택기, 대기 승인 배지(클릭 시 드롭다운으로 승인 목록), 연결 상태 인디케이터(WebSocket·Discord·GitHub)를 가진다.

## 3. 화면 설계

### 3.1 Task 목록 `/tasks`

상단에 상태 필터 칩(전체 / 진행 중 / 승인 대기 / 차단 / 완료 / 실패)과 "새 Task" 버튼. 본문은 카드 그리드가 아니라 **행 목록**이다. 한 행에 Task 제목(명령 첫 줄), 현재 Stage 미니 파이프라인(6개 점, 완료·진행·대기·반려를 색으로), 대기 승인 배지, 경과 시간, 토큰 사용량 바, 마지막 이벤트 한 줄 요약이 들어간다. 승인 대기 행은 왼쪽 테두리를 강조색으로 칠한다. 행 클릭으로 상세 진입.

빈 상태에는 "Discord에서 `/task`로 시작하거나 여기서 새 Task를 만드세요"와 예시 명령 세 개를 보여 준다.

### 3.2 새 Task `/tasks/new`

프로젝트 선택, 명령 입력(멀티라인, 예시 placeholder), 고급 옵션 접기(토큰 예산 override, 특정 Stage 건너뛰기 — Phase 3). 제출하면 상세 화면으로 이동하며 첫 이벤트가 흐르기 시작한다.

### 3.3 Task 상세 `/tasks/:id` ★

레이아웃은 데스크톱 기준 3구역이다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ ← Tasks   회원 탈퇴 기능 추가          [waiting_approval] ⏸ ✖  ⚙   │
│ ● 기획 ─── ● 디자인 ─── ◐ FE ─┐                                       │
│                          ◐ BE ─┴─ ○ 검수 ─── ○ PR      (파이프라인)  │
├───────────────────────────────────┬──────────────────────────────────┤
│ Agent 카드 (가로 스크롤 또는 2x2)   │  승인 패널 (대기 중이면 최상단)    │
│ ┌기획──┐ ┌디자인┐ ┌FE───┐ ┌BE───┐ │  ┌──────────────────────────────┐│
│ │✓ 완료│ │✓ 완료│ │⟳ 실행│ │⟳ 실행│ │  │ [Plan] FE agent 계획 v1      ││
│ │      │ │      │ │"컴포넌│ │"API │ │  │ ─────────────────────────── ││
│ │      │ │      │ │트 작성│ │엔드포│ │  │ 1. WithdrawalModal 컴포넌트  ││
│ └──────┘ └──────┘ └──────┘ └──────┘ │  │ 2. useWithdrawal hook       ││
│                                    │  │ ...                          ││
│ 타임라인 (실시간, 최신이 아래)        │  │ [✅ 승인] [✏️ 수정] [❌ 반려]  ││
│ 10:02:11 FE  🔧 read_file src/... │  └──────────────────────────────┘│
│ 10:02:13 BE  💭 "탈퇴 유예는 soft  │                                  │
│              delete + deleted_at" │  산출물 (탭: 기획 spec · 디자인 · │
│ 10:02:15 BE  🔧 write_file api/.. │   FE diff · BE diff · 검수 리포트)│
│ 10:02:20 FE  📄 deliverable 제출   │  ┌──────────────────────────────┐│
│ [필터: agent ▾  타입 ▾  ⏸ 자동스크롤]│  │  Markdown / diff 뷰어         ││
│                                    │  └──────────────────────────────┘│
└───────────────────────────────────┴──────────────────────────────────┘
```

**파이프라인 바**는 `pipeline.yaml`의 Stage를 왼쪽에서 오른쪽으로 배치하고 `depends_on`이 같은 Stage는 세로로 쌓아 병렬을 표현한다. 각 노드는 상태 아이콘(○ 대기, ◐ 진행, ● 완료, ⟲ 반려 후 재작업, ✕ 실패)과 클릭 시 해당 Stage의 Plan·Deliverable·승인 이력으로 스크롤한다.

**Agent 카드**는 역할 아바타, 상태 배지, "지금 생각" 한 줄(`agent.thinking` 최신 summary, 2초 이상 갱신 없으면 흐리게), 마지막 도구 호출, 이번 Stage 토큰 사용량을 담는다. 실행 중인 카드는 테두리가 부드럽게 맥동한다. 카드 클릭은 타임라인을 그 agent로 필터링한다.

**타임라인**은 가상 스크롤 리스트다. 이벤트 타입별 아이콘(💭 thinking, 🔧 tool_call, ✅/⚠️ tool_result, 💬 message, 📄 deliverable, 🙋 approval, ▶/■ stage)과 agent 색 점, 상대 시간을 붙인다. tool_call과 tool_result는 한 쌍으로 접히고 펼치면 args·result 요약이 보인다. 자동 스크롤은 사용자가 위로 올리면 멈추고 "새 이벤트 N개 ↓" 버튼이 뜬다.

**승인 패널**은 대기 중인 Approval이 있으면 오른쪽 상단에 고정된다. 헤더에 종류(Plan/Deliverable)·agent·버전(retry_no)·제출 시각, 본문에 Markdown 원문(Deliverable이 코드면 diff 뷰어), 하단에 세 버튼. 반려는 인라인 텍스트 영역이 펼쳐지며 피드백이 비어 있으면 제출이 막힌다. 수정은 본문이 편집기로 바뀌고 "수정 후 승인" 버튼으로 확정된다. 결정 후에는 "승인됨 · 웹 · 10:05 · Jin Ho" 같은 이력 줄로 접히고, 다음 대기 승인이 있으면 그것이 올라온다. Discord에서 이미 결정된 경우 패널이 실시간으로 이력 상태로 바뀐다.

**산출물 뷰어**는 Stage별 탭이며 Markdown 렌더링, unified/split diff, JSON 트리를 지원한다. 전체 화면 버튼으로 `/tasks/:id/deliverables/:did`로 이동.

모바일(≤ 768px)에서는 3구역이 세로 탭(파이프라인 상단 고정 + "현황 / 승인 / 산출물" 탭)으로 바뀌고, 승인 패널 탭에 대기 수 배지를 단다. 폰에서 Discord 대신 웹으로 승인하는 경로를 막지 않기 위해서다.

### 3.4 팀원 설정 `/projects/:id/agents`

이 화면은 "사용자가 자기 팀을 구성하는 곳"이다. 왼쪽에는 `.devsquad/agents/`에서 읽은 **팀원 목록**(아바타 색, display_name, tool_profile 배지, 파이프라인에서의 위치 미니 표시)과 하단의 **"팀원 추가"** 버튼이 있다. 추가 버튼은 템플릿 갤러리 모달을 연다: 서비스 제공 템플릿(planner, designer, backend, frontend, reviewer, qa) 카드와 "빈 팀원" 카드가 있고, 카드마다 한 줄 소개·tool_profile·결과물 위치가 적혀 있다. 템플릿을 고르고 이름을 입력하면 서비스가 폴더를 repo에 커밋하고 목록에 나타난다.

오른쪽은 선택한 팀원의 편집 영역이다. 상단 헤더에 display_name, tool_profile 선택(드롭다운 4종), `write_paths` 칩 편집, `test_command`(code-writer일 때), 색 선택. 그 아래 탭 세 개: `persona.md`(4절 구조를 접이식 섹션으로 안내), `conventions.md`(6절 구조, 각 절 옆에 "이 절이 왜 중요한지" 힌트 아이콘), `knowledge/`(파일 목록·업로드·삭제, README.md의 설명 표를 파싱해 파일 옆에 표시). 저장은 GitHub 커밋(`chore(devsquad): update <name> conventions`)으로 이루어지며 저장 전 diff 미리보기를 보여 준다.

우측 상단에 **검증 상태** 배지가 있다: 필수 파일 존재, 프론트매터 유효, `write_paths`가 다른 팀원과 충돌하지 않음, `pipeline.yaml`에서 참조됨. 하나라도 실패하면 빨간 배지와 이유를 보여 준다. "이 팀원으로 테스트 실행" 버튼(Phase 3)은 자리만 잡아 둔다.

팀원 삭제는 폴더 삭제가 아니라 `pipeline.yaml`에서 Stage를 빼는 것으로 안내하고(폴더는 남아 재사용 가능), 폴더까지 지우는 것은 확인 다이얼로그 뒤에 별도 커밋으로 한다.

### 3.5 Project 목록·연결 `/projects`

GitHub App 설치 버튼, 설치된 repo 목록에서 선택해 Project 생성, `.devsquad/` 존재 여부 검사 후 없으면 "기본 템플릿 커밋" 제안.

## 6. 접근성과 상태 표현

색만으로 상태를 구분하지 않고 항상 아이콘·텍스트를 병기한다. 승인 버튼은 키보드 단축키(A 승인, R 반려, E 수정)를 제공하고 포커스 순서는 본문 → 버튼이다. 타임라인은 `aria-live="polite"` 영역으로 새 이벤트를 스크린리더에 알리되 thinking은 제외한다.

## 7. 디자인 agent에게 넘길 산출물 형식 (참고)

이 문서는 사람이 쓴 것이지만, 앞으로 디자인 agent가 만들 산출물도 같은 형식을 따르게 `designer/conventions.md`에 명시한다: 화면별 (1) 목적 한 줄, (2) ASCII 또는 Mermaid 레이아웃, (3) 컴포넌트 인벤토리 표, (4) 상태·빈 상태·오류 상태, (5) 사용하는 디자인 토큰. 이 형식이면 FE agent가 기계적으로 컴포넌트 트리로 옮길 수 있다.
