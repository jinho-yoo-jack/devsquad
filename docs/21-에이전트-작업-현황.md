# 21. 에이전트 작업 현황

기록일: 2026-10-06. Go 통합 구현 이후 요청된 프론트 기능이다. [19번 설계](19-Go-통합-서비스-설계.md)의 웹 제외 범위에 대한 후속 확장이며, 공개 REST 구조와 기존 이벤트 type은 유지한다.

## 사용자 화면

Task 상세 상단에 **에이전트 작업 현황**을 표시한다. 카드 순서는 파이프라인 의존 관계를 따른다.

- 에이전트 이름과 단계, 계획·실행·승인 대기·완료·차단 상태
- 파일 읽기·작성, 코드 검색, 테스트, 모델 응답 대기 등 현재 동작
- 최근 도구 결과, 승인·선행 단계 대기 이유, 모델·호출 회차와 마지막 활동 시각
- 카드 선택 시 해당 단계만 타임라인에 표시, 다시 선택하거나 필터 해제로 전체 보기
- 작은 화면에서는 카드를 한 열로 표시

Task가 취소·실패하면 과거 도구 실행을 진행 중으로 표시하지 않는다. 일시정지는 새 단계 시작을 막지만 이미 진행 중인 작업은 마무리될 수 있다는 안내를 표시한다. WebSocket이 끊어지면 마지막 수신 상태임을 안내하고 카드의 실행 애니메이션을 멈춘다.

## 데이터와 복구

생명주기 상태는 REST Task·Stage를 기준으로 삼고, 작업 설명은 단계별 이벤트에서 읽는다. 같은 역할이 여러 단계를 맡을 수 있으므로 `agent` 대신 `stage_key`로 활동을 집계한다. 도구 호출 결과는 단계·역할·호출 ID로 연결하고 호출 이벤트 ID별로 보존하여 병렬 실행이나 재시도에서 ID가 재사용돼도 이력이 섞이지 않는다.

Go runner는 각 모델 호출 직전에 `agent.thinking`을 발행한다. 기존 `summary`에 `iteration`, `model`을 추가했으며 과거 이벤트도 표시할 수 있다. 첫 호출 이벤트는 Task를 재조회하여 승인 게이트가 없는 계획 → 실행 전이를 반영한다.

초기 로드와 재연결 시 REST 이벤트를 마지막 페이지까지 병합한다. 느린 초기 응답이 이미 수신한 WS 이벤트를 덮어쓰지 않는다. 500건보다 큰 seq 공백도 여러 페이지를 조회해 채운다. 재연결 시 Task·Approval도 다시 조회한다.

Next.js의 `/ws` 프록시를 `/api/*`와 같은 Go 서비스에 연결한다. 프로덕션 rewrites는 빌드 시 결정되므로 Docker build arg와 Compose의 `CONTROL_PLANE_URL`도 함께 지정한다.

## 직접 실행한 검증

- TypeScript 타입 검사, Vitest 44개, Next.js 프로덕션 빌드 통과.
- Go 전체 race 테스트·vet·바이너리 빌드, 실제 PostgreSQL 통합 테스트 통과. 모델 호출 시마다 먼저 활동 이벤트가 발행되는 plan/execute 테스트 추가.
- Chromium 브라우저 테스트: 같은 역할의 병렬 단계와 같은 호출 ID 분리, 카드 선택 필터, 도구 오류, 승인 대기, WS 단절·재연결, 새로고침 복원, 취소, 390px 모바일 화면의 가로 넘침 없음 확인. HTTP/WS fixture로 실행하며 외부 모델을 호출하지 않는다.
- 실제 Go + PostgreSQL + Next.js + Chromium: 예제 6개 에이전트 카드, `/api`·`/ws` 프록시, 화면에서 계획 승인 → write_file 완료 → 산출물 승인 대기, 새로고침 복원과 취소 상태 반영 확인. 이 검증은 FakeLLM을 사용했다.
- 웹 Docker 이미지 빌드와 Compose 설정 검증 통과. 최종 이미지의 routes manifest에서 `/api/*`·`/ws` 목적지가 모두 `http://devsquad:8080`으로 고정됨을 확인했다.

브라우저 테스트는 `cd web && npx playwright install chromium && npm run e2e`로 재현한다. CI에도 포함했다. 초기 실행 때 로컬 Playwright에 맞는 Chromium이 없어 설치한 후 통과했다. 검증용 DB·서비스와 임시 workspace는 종료·정리했다.
